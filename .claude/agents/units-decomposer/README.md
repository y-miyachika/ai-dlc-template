# Units Decomposer SubAgent

ソフトウェアアーキテクチャとDDD専門のユニット分解SubAgent

## 概要

インテントまたはBacklogを、**疎結合・高凝集**のユニットに分解するSubAgentです。

**DDD原則**: サブドメイン、境界コンテキスト、ユビキタス言語を活用

## 特徴

### 1. DDD（ドメイン駆動設計）に基づく分解

**サブドメインの分類**:
- **コアドメイン**: ビジネスの競争優位性
- **サポートドメイン**: コアを支える機能
- **汎用ドメイン**: 既製品で十分な機能

**境界コンテキスト**:
- ユビキタス言語の境界
- モデルの一貫性の境界
- チームの境界

### 2. 疎結合・高凝集の原則

**疎結合（Loose Coupling）**:
- ユニット間の依存関係を最小化
- インターフェースを通じた通信
- イベント駆動アーキテクチャの活用

**高凝集（High Cohesion）**:
- 関連する機能を1つのユニットにまとめる
- 単一責任の原則（SRP）
- 変更理由が同じものをまとめる

### 3. 実装順序の推奨

以下の観点で実装順序を決定：
- 依存関係（依存されるユニットを先に）
- ビジネス価値（価値の高いユニットを優先）
- リスク（リスクの高いユニットを早期検証）

## 使い方

### AI-DLCテンプレート内で使用

```bash
# 最新のインテント/Backlogを分解
/units

# 特定のインテント/Backlogを分解
/units 047
```

### 他プロジェクトで使用

このSubAgentは、AI-DLCテンプレート以外のプロジェクトでも利用可能です：

1. `.claude/agents/units-decomposer/` をコピー
2. プロジェクトに配置
3. SubAgentを呼び出し

## 処理フロー

```
1. インテント/Backlogの読み込み
   ↓
2. ドメイン分析（DDD観点）
   - サブドメインの特定
   - 境界コンテキストの特定
   - 技術的境界の特定
   ↓
3. ユニット分解の原則適用
   - 疎結合・高凝集
   - チーム規模、デプロイ単位を考慮
   ↓
4. ユニット定義の生成
   - 責務、インターフェース、依存関係
   - 実装スコープ（Lambda Handlers含む）
   ↓
5. 依存関係の可視化
   ↓
6. 実装順序の推奨
   ↓
7. ユーザー承認
   ↓
8. ファイル保存（docs/units/）
```

## ユニット分解の良い例 vs 悪い例

### ✅ 良い例（適切な粒度）

```
ユニット1: ユーザー管理
- ユーザー登録
- ユーザー認証
- プロフィール管理

ユニット2: 商品管理
- 商品カタログ
- 在庫管理
- 価格設定
```

**理由**: 関連する機能をまとめ、独立してデプロイ可能

### ❌ 悪い例（過度な分割 - Nanoサービス）

```
ユニット1: ユーザー登録のみ
ユニット2: ユーザー認証のみ
ユニット3: プロフィール管理のみ
```

**問題**: 粒度が細かすぎて、管理コストが増大

---

### ✅ 良い例（疎結合）

```
ユニット1 →[API]→ ユニット2 →[Event]→ ユニット3
```

**理由**: API/イベントを通じた通信で、独立性を保つ

### ❌ 悪い例（密結合）

```
ユニット1 ←→ ユニット2 ←→ ユニット3
（相互依存、共有データベース）
```

**問題**: 変更が波及し、独立したデプロイが困難

---

## AI-DLC原則との対応

| 原則 | 実装方法 |
|-----|---------|
| **会話の逆転** | ユニット分解案を提示し、ユーザーの承認を得る |
| **損失関数** | 適切な粒度で分割し、下流の無駄な作業を防ぐ |
| **コンテキストメモリ** | ユニット分解結果を永続化 |
| **段階的詳細化** | インテント → ユニット → ドメイン → コード |
| **疎結合・高凝集** | DDDのサブドメイン、境界コンテキストを活用 |

## SubAgent vs Skill

**なぜSubAgentなのか**:

- **ドメイン分析**: サブドメイン、境界コンテキストの深い分析
- **多段階思考**: DDD原則を適用し、最適なユニット構成を検討
- **対話型**: ユーザーに分解案を提示し、承認を得る

**Skillとの違い**:

| 項目 | Skill | SubAgent |
|-----|-------|----------|
| **実行形式** | 単発処理 | 多段階思考 |
| **用途** | コード生成 | アーキテクチャ設計 |
| **思考の深さ** | 浅い | 深い（DDD分析） |
