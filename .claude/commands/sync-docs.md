# 設計ドキュメント同期チェック

変更されたファイルと関連するUnit/設計ドキュメントを検出し、更新が必要な箇所を提案します。

## 用途

コード変更後に、設計ドキュメントとの乖離をチェックします。
- 実装がドキュメントと一致しているか確認
- 更新が必要なドキュメントを特定
- 具体的な更新提案を提示

## 引数

- パッケージ名またはUnit番号（省略時は全体をチェック）

## 実施内容

### 1. 変更ファイルの検出

```bash
# 直近のコミットで変更されたファイル
git diff --name-only HEAD~1

# または、ステージングされた変更
git diff --name-only --staged

# または、未コミットの変更すべて
git diff --name-only HEAD
```

### 2. 関連ドキュメントの特定

変更されたファイルから、関連するドキュメントをマッピング：

| 変更ファイル | 関連ドキュメント |
|------------|----------------|
| `packages/{pkg}/src/domain/**` | `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/domain.md` |
| `packages/{pkg}/src/services/**` | `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/domain.md` |
| `packages/{pkg}/src/routes/**` | `docs/api/openapi.yaml` |
| `terraform/**` | `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/architecture.md` |
| `*.test.ts` | `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/tests.md` |

### 3. 乖離チェック

各関連ドキュメントについて、以下を確認：

#### ドメイン設計との乖離

- [ ] 新しいエンティティ/値オブジェクトが追加されていないか
- [ ] 既存のドメインモデルの構造が変更されていないか
- [ ] 新しいドメインイベントが追加されていないか
- [ ] ユビキタス言語に新しい用語が追加されていないか

#### アーキテクチャ設計との乖離

- [ ] 新しいコンポーネントが追加されていないか
- [ ] データフローが変更されていないか
- [ ] 技術スタックが変更されていないか
- [ ] 新しい外部依存が追加されていないか

#### テスト設計との乖離

- [ ] 新しいテストケースが追加されていないか
- [ ] テスト境界が変更されていないか

### 4. 結果レポート

```markdown
## 同期チェック結果

### 変更されたファイル

- `packages/api/src/domain/entities/User.ts` (modified)
- `packages/api/src/services/user.service.ts` (modified)
- `packages/api/src/domain/entities/UserProfile.ts` (added)

### 関連ドキュメント

| ドキュメント | ステータス | 必要なアクション |
|------------|----------|----------------|
| `docs/intents/001_ユーザー管理/001_user/domain.md` | ⚠️ 更新推奨 | UserProfile エンティティを追加 |
| `docs/intents/001_ユーザー管理/001_user/tests.md` | ⚠️ 更新推奨 | UserProfile のテストケースを追加 |
| `docs/api/openapi.yaml` | ✅ 同期済み | - |

### 更新提案

#### 1. `docs/intents/001_ユーザー管理/001_user/domain.md`

**追加が必要な内容**:

```markdown
### UserProfile（エンティティ）

| 属性 | 型 | 説明 |
|-----|---|------|
| userId | UserId | ユーザーID（外部キー） |
| displayName | string | 表示名 |
| avatarUrl | string | アバター画像URL |
```

#### 2. `docs/intents/001_ユーザー管理/001_user/tests.md`

**追加が必要な内容**:

```markdown
### UserProfile テストケース

- [ ] プロフィール作成
- [ ] プロフィール更新
- [ ] プロフィール取得
```
```

### 5. ユーザー確認

3. 後で手動対応
4. キャンセル

```

## 使用例

```bash
# 全体チェック
/sync-docs

# 特定パッケージ
/sync-docs api

# 特定Unit
/sync-docs 001
```

## バックグラウンド実行

`/sync-docs` はバックグラウンドで実行することで、メインの開発作業を止めずに乖離チェックが可能です。

**手動でバックグラウンド実行する場合**:
Task toolで `run_in_background: true` を指定して起動。結果は `output_file` パスから確認できます。

```
Task(subagent_type: "general-purpose", run_in_background: true, prompt: "/sync-docs を実行")
```

**`/bolt` 完了後の自動実行（推奨）**:
`/bolt` のPhase 3（Refactor）完了時に、sync-docsをバックグラウンドで自動起動することを推奨します。
リファクタリング後のドキュメント乖離を、次のタスクに取りかかりながら検出できます。

## 乖離パターンと対応

### パターン1: 新規エンティティ追加

**検出**: `src/domain/entities/` に新規ファイル

**対応**:
- ドメイン設計ドキュメントに追加
- テスト設計ドキュメントに追加

### パターン2: APIエンドポイント変更

**検出**: `src/routes/` のファイル変更

**対応**:
- OpenAPI仕様の更新
- アーキテクチャ設計のデータフロー確認

### パターン3: インフラ変更

**検出**: `terraform/` のファイル変更

**対応**:
- アーキテクチャ設計ドキュメントの更新
- デプロイドキュメントの確認

### パターン4: 依存関係変更

**検出**: `package.json` の変更

**対応**:
- 技術スタックセクションの更新
- 必要に応じてADRの追加

---

## 自動更新の範囲

以下は自動更新の**提案のみ**（実際の更新はユーザー承認後）：

- ドメインモデルへのエンティティ/値オブジェクト追加
- テストケースの追加
- 技術スタックの更新

以下は**手動更新を推奨**：

- アーキテクチャパターンの変更
- NFRの変更
- ADRの新規作成

---

## 注意事項

1. **破壊的変更の警告**: ドキュメントの既存内容を削除する場合は警告
2. **コンフリクト防止**: 複数の変更が同じセクションに影響する場合は確認
3. **バックアップ**: 更新前に既存ドキュメントのバックアップを推奨

## AI-DLC原則との対応

| 原則 | 実装方法 |
|-----|---------|
| **トレーサビリティ** | コード変更 ↔ 設計ドキュメントの紐付け |
| **継続的改善** | 乖離の早期検出と修正 |
| **設計技術の統合** | DDD成果物と実装の整合性維持 |
