# ユニット分解（AI-DLC準拠）

最新のBacklogを読み込み、AI-DLC（AI-Driven Development Lifecycle）の原則に基づいて、**疎結合・高凝集**のユニットに分解してください。

## 入力

引数として以下のいずれかを受け取ります：
- Backlog番号（例: `046`）
- 省略時は最新のBacklog

```
{{ARGS}}
```

## あなたの役割

経験豊富なソフトウェアアーキテクトとして、以下のステップでユニット分解を実行してください。

---

## ステップ1: Backlogの読み込みと分析

1. 指定されたBacklog（または最新）を `docs/backlog/` から読み込む
2. ユーザーストーリーを全て抽出
3. 非機能要件（NFR）を確認

---

## ステップ2: ユニット分解の原則

以下の原則に基づいてユニットに分解してください：

### 疎結合（Loose Coupling）
- ユニット間の依存関係を最小化
- インターフェースを通じた通信
- 独立したデプロイが可能

### 高凝集（High Cohesion）
- 関連する機能を1つのユニットにまとめる
- 単一責任の原則（SRP）
- ドメイン駆動設計（DDD）のサブドメイン概念

### その他の考慮事項
- チーム規模: 1ユニットは1チームで構築可能
- デプロイ単位: 独立してデプロイ可能
- 技術的境界: 異なる技術スタック間の境界

## 注意事項

1. **過度な分割を避ける**: マイクロサービスの罠（Nanoサービス）に注意
2. **共通機能の抽出**: 複数ユニットで使われる機能は共有ライブラリ化
3. **境界コンテキストの尊重**: DDDの境界コンテキストを意識
4. **段階的な分割**: 最初は粗く分割し、必要に応じて細分化
5. **チームの能力を考慮**: 技術的に実現可能な分割か確認

## ユニット分解完了後の確認事項

ユーザーに以下を確認してください：

- [ ] ユニットの責務分担は適切ですか？
- [ ] 依存関係は最小化されていますか？
- [ ] 各ユニットは独立してデプロイ可能ですか？
- [ ] 実装順序は妥当ですか？
- [ ] NFRの割り当ては適切ですか？

確認後、`docs/units/[Backlog番号]_units.md` に保存してください。
