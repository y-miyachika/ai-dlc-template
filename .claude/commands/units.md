# ユニット分解（AI-DLC準拠）

このコマンドは**Units Decomposer SubAgent**を使用して、インテント/Backlogをユニットに分解します。

## SubAgentについて

`units-decomposer` SubAgentは、DDD（ドメイン駆動設計）原則に基づき、**疎結合・高凝集**のユニットに分解する専門SubAgentです。

**DDD原則**: サブドメイン、境界コンテキスト、ユビキタス言語を活用

詳細は `.claude/agents/units-decomposer/README.md` を参照してください。

---

引数として以下のいずれかを受け取ります：
- インテント番号（例: `047`）
- Backlog番号（例: `046`）
- 省略時は最新のインテント/Backlog

## SubAgent起動

以下を実行します：

1. **インテント/Backlogの読み込み**: `docs/intents/` または `docs/backlog/` から読み込み
2. **ドメイン分析**: サブドメイン、境界コンテキスト、技術的境界を特定
3. **ユニット分解**: 疎結合・高凝集の原則でユニットを定義
4. **依存関係の可視化**: ユニット間の依存関係を図示
5. **実装順序の推奨**: 依存関係、ビジネス価値、リスクを考慮
6. **ユーザー承認**: 分解案を提示し、承認を得る
7. **ファイル保存**: `docs/units/{番号}_units.md` に保存

## SubAgent処理の詳細

SubAgentは `.claude/agents/units-decomposer/prompt.md` に定義された手順に従って処理を実行します。

**主要な処理**:

1. ドメイン分析（DDD観点）
   - サブドメインの特定（Core/Supporting/Generic）
   - 境界コンテキストの特定
   - 技術的境界の特定

2. ユニット分解の原則適用
   - 疎結合（依存関係の最小化）
   - 高凝集（関連機能のまとめ）
   - チーム規模、デプロイ単位を考慮

3. ユニット定義の生成
   - 責務、インターフェース、依存関係
   - 実装スコープ（Lambda Handlers含む）
   - NFR割り当て、リスク評価

**テンプレート詳細**: `.claude/agents/units-decomposer/prompt.md` を参照

## DDD原則に基づくユニット分解

### 疎結合（Loose Coupling）
- ユニット間の依存関係を最小化
- インターフェースを通じた通信
- イベント駆動アーキテクチャの活用

### 高凝集（High Cohesion）
- 関連する機能を1つのユニットにまとめる
- 単一責任の原則（SRP）
- 変更理由が同じものをまとめる

### サブドメイン分類
- **コアドメイン**: ビジネスの競争優位性
- **サポートドメイン**: コアを支える機能
- **汎用ドメイン**: 既製品で十分な機能


## 注意事項

1. **過度な分割を避ける**: マイクロサービスの罠（Nanoサービス）に注意
2. **共通機能の抽出**: 複数ユニットで使われる機能は共有ライブラリ化
3. **境界コンテキストの尊重**: DDDの境界コンテキストを意識
4. **段階的な分割**: 最初は粗く分割し、必要に応じて細分化
5. **チームの能力を考慮**: 技術的に実現可能な分割か確認
