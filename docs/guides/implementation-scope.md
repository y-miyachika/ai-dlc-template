# 実装スコープ定義ガイド

このガイドでは、各コマンドの実装スコープと完了条件を明確に定義します。「何をもって完了とするか」を明確にし、曖昧さを排除します。

## コマンド別スコープ定義

### /intent - インテント定義

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| ビジネス価値の明確化 | 技術的な実装詳細 |
| ユーザーストーリー（As a / I want / So that） | データベース設計 |
| 受入基準（BDD形式） | API仕様 |
| 非機能要件（NFR） | コード |
| リスクと依存関係 | テストコード |

#### 完了条件チェックリスト

- [ ] ユーザーストーリーが明確（誰が、何を、なぜ）
- [ ] 受入基準が BDD 形式で記述されている
- [ ] NFR が具体的な数値で定義されている
- [ ] リスクが識別され、対策が検討されている
- [ ] `docs/intents/{Intent番号}_{Intent名}/intent.md` が生成されている

#### 出力例

```
docs/intents/001_ユーザー認証機能/intent.md
```

---

### /units - ユニット分解

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| ユニット一覧と責務 | 各ユニットの実装詳細 |
| ユニット間の依存関係 | データモデル |
| 境界の定義 | API設計 |
| 推奨実装順序 | テストケース |

#### 完了条件チェックリスト

- [ ] 各ユニットの責務が明確（1文で説明可能）
- [ ] 境界が定義されている（何を含み、何を含まないか）
- [ ] 依存関係が図示されている
- [ ] 循環依存がない
- [ ] 実装順序が決定している
- [ ] `docs/intents/{Intent番号}_{Intent名}/units.md` が生成されている

#### 出力例

```
docs/intents/001_ユーザー認証機能/units.md
```

### /design-domain - ドメイン設計

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| エンティティ定義 | HTTPエンドポイント |
| 値オブジェクト定義 | データベーススキーマ |
| 集約とルートエンティティ | インフラ設定 |
| ドメインサービス | UIコンポーネント |
| リポジトリインターフェース | 具体的な実装コード |
| ユビキタス言語 | |

#### 完了条件チェックリスト

- [ ] エンティティが識別され、属性が定義されている
- [ ] 値オブジェクトが適切に分離されている
- [ ] 集約境界が明確
- [ ] ドメインルール（不変条件）が記述されている
- [ ] リポジトリインターフェースが定義されている
- [ ] `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/domain.md` が生成されている

#### 出力例

```
docs/intents/001_ユーザー認証機能/001_認証ドメイン/domain.md
```

### /design-architecture - アーキテクチャ設計

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| アーキテクチャパターン選択 | 実装コード |
| NFR対応策 | テストコード |
| コンポーネント図 | 運用手順 |
| トレードオフ分析 | モニタリング設定 |
| ADR（決定記録） | |
| 外部API制約の考慮 | |

#### 完了条件チェックリスト

- [ ] アーキテクチャパターンが選択されている
- [ ] 選択理由がトレードオフと共に記述されている
- [ ] NFRへの対応策が具体的
- [ ] コンポーネント図が作成されている
- [ ] ADRが生成されている
- [ ] `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/architecture.md` が生成されている
- [ ] `docs/adr/ADR-{連番}_{タイトル}.md` が生成されている

#### 出力例

```
docs/intents/001_ユーザー認証機能/001_認証ドメイン/architecture.md
docs/adr/ADR-001_認証パターン選択.md
```

### /design-test - テスト設計

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| テストケース一覧 | 実際のテストコード |
| テスト優先度（P0/P1/P2） | テスト実行 |
| テストピラミッド構成 | CI/CD設定 |
| モック/スタブ戦略 | |
| BDD → TDD マッピング | |

#### 完了条件チェックリスト

- [ ] BDD受入基準からテストケースが導出されている
- [ ] テストピラミッド（Unit/Integration/E2E）が定義されている
- [ ] 各テストケースに優先度が付与されている
- [ ] モック/スタブ戦略が決定している
- [ ] `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/tests.md` が生成されている

#### 出力例

```
docs/intents/001_ユーザー認証機能/001_認証ドメイン/tests.md
```

### /bolt - 実装サイクル

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| ドメイン層の実装 | HTTP層（API） |
| サービス層の実装 | インフラ層（IaC） |
| リポジトリ実装 | デプロイ設定 |
| ユニットテスト | E2Eテスト |
| インテグレーションテスト | 運用ドキュメント |
| 実装計画（Intent階層内のplan.md） | |

#### 完了条件チェックリスト

- [ ] ドメイン層が実装されている
- [ ] サービス層が実装されている
- [ ] リポジトリが実装されている
- [ ] ユニットテストが全てパス
- [ ] インテグレーションテストが全てパス
- [ ] 型エラーがない
- [ ] `docs/intents/{Intent番号}_{Intent名}/{Unit番号}_{Unit名}/plan.md` が生成/更新されている
- [ ] `src/` または `packages/` に実装コードがある
- [ ] `tests/` にテストコードがある

#### 出力例

```
src/domain/auth/
├── entities/
├── value-objects/
├── services/
└── repositories/

tests/
├── unit/
└── integration/

docs/intents/001_ユーザー認証機能/001_認証ドメイン/plan.md
```

### /generate-api - API生成

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| HTTPエンドポイント | ドメインロジック |
| リクエスト/レスポンス型 | データベース接続 |
| OpenAPI仕様 | 認証/認可の実装 |
| バリデーション | インフラ設定 |
| エラーハンドリング | |

#### 前提条件

- `/bolt` で services 層が実装済みであること

#### 完了条件チェックリスト

- [ ] HTTPエンドポイントが実装されている
- [ ] リクエスト/レスポンス型が定義されている
- [ ] OpenAPI仕様が生成されている
- [ ] バリデーションが実装されている
- [ ] エラーハンドリングが実装されている
- [ ] `packages/api/` または `apps/api/` にコードがある
- [ ] `docs/api/` にOpenAPI仕様がある

#### スコープ

| 含まれるもの | 含まれないもの |
|-------------|--------------|
| Terraform/Terragruntモジュール | アプリケーションコード |

| IAMポリシー | モニタリング設定 |

- `/design-architecture` でアーキテクチャ設計が完了していること

- [ ] Terraformモジュールが生成されている

- [ ] IAMポリシーが最小権限原則に従っている
- [ ] `terraform/` ディレクトリにコードがある
- [ ] `terraform plan` が成功する

## Unit完了の全体チェックリスト

1つのUnitが完了したと見なすための包括的なチェックリスト：

### 必須項目

- [ ] **設計完了**
  - [ ] ドメイン設計ドキュメント作成済み
  - [ ] アーキテクチャ設計ドキュメント作成済み
  - [ ] テスト設計ドキュメント作成済み

- [ ] **実装完了**
  - [ ] ドメイン層実装済み
  - [ ] サービス層実装済み
  - [ ] リポジトリ層実装済み
  - [ ] 実装計画（Intent階層内のplan.md）更新済み

- [ ] **テスト完了**
  - [ ] ユニットテスト全パス
  - [ ] インテグレーションテスト全パス
  - [ ] 型チェック（`tsc --noEmit`）成功

- [ ] **品質基準**
  - [ ] 型エラーなし
  - [ ] Lint警告なし（許容範囲内）
  - [ ] セキュリティ脆弱性なし

### オプション項目（必要に応じて）

- [ ] **API層**（/generate-api 使用時）
  - [ ] HTTPエンドポイント実装済み
  - [ ] OpenAPI仕様生成済み

- [ ] **インフラ層**（/generate-iac 使用時）
  - [ ] Terraformモジュール作成済み
  - [ ] `terraform plan` 成功

- [ ] **デプロイ設定**（/generate-deploy 使用時）
  - [ ] GitHub Actions設定済み
  - [ ] デプロイスクリプト作成済み

## スコープ外の作業

以下は AI-DLC スラッシュコマンドのスコープ外です：

| カテゴリ | 作業内容 | 対応方法 |
|---------|---------|---------|
| 運用 | モニタリング設定 | 手動または /operate（未実装） |
| 運用 | アラート設定 | 手動 |
| 運用 | ログ集約 | 手動 |
| セキュリティ | 脆弱性スキャン | CI/CDで自動化 |
| セキュリティ | シークレット管理 | AWS Secrets Manager等を手動設定 |
| パフォーマンス | 負荷テスト | 別途ツール使用 |
| ドキュメント | ユーザーマニュアル | 手動作成 |
